# 馬可小幫手

Super Marco 供應商後台（supply-admin.super-marco.com）的 Chrome 書籤小工具。辦公室電腦在後台頁面上按書籤「馬可小幫手」，會跳出功能選單：

| 功能 | 做什麼 |
|---|---|
| 📋 檢查待接單 | 找出「明天配送」的待審核訂單，自動檢查下單備註和商品備註，分成 🟢 可直接接單／🔴 有備註要看，勾選後一次接單 |
| 💲 更新批次價格 | 勾選批次 → 用**當天**的價格檔（每天 17:00 自動備份）一鍵更新價格：匯出 → 填「盤價-定價」→ 匯入 → 再匯出核對。只有異常才顯示紅色通知 |
| 🖨️ 產生出貨單 | 先把還沒分配的訂單自動分配車次（配送路線 1車→A … 6車→F），再依車號排序，產生 A5 出貨明細（同車同客人排一起） |
| ☀️ 會計早上核對 | 今天到貨的訂單一次檢查：重量／數量可疑（跟理貨表格回填值比對、台斤公斤搞混、秤重品沒秤）、實價／外購品（價格 0）、運費（同客戶當天合併 vs 運費群組門檻）。**第一階段只檢查不改資料** |
| 📝 常態 OK 清單 | 打開 Google 試算表：客人固定的備註（例如「高麗菜加工 10 斤裝一袋」）經主管核准後，以後檢查就算 🟢 |

## 一、整體架構

```
各台電腦的 Chrome 書籤「馬可小幫手」
   │  （書籤裡只有一句：去下面的網址拿最新程式）
   ▼
GitHub Pages：https://david840822-create.github.io/marco-tools/mk.js   ← 功能選單
   ├─ accept.js   檢查待接單（按到才載入）
   ├─ price.js    更新批次價格（按到才載入）
   └─ print.js    產生出貨單（按到才載入）
         │
         │ 在「目前開著的後台頁面」裡執行，用隱藏 iframe 打開後台自己的頁面、讀畫面、按按鈕
         │ （權限 = 當下登入後台那個人的權限，工具沒有額外權限）
         ▼
馬可供應商後台

accept.js ⇄ Google Apps Script 網路程式 ⇄ Google 試算表「馬可小幫手｜常態OK備註清單」
            （讀已核准清單 / 小姐送審）            （主管把狀態改成「核准」）

price.js ⇄ Apps Script 網路程式（專案「每日報價自動備份」，要密碼）⇄ Google 雲端「YYYY年M月報價資料／商品分組價(行政每日更新價格) Mdd.xlsx」
```

**改程式 = 更新 GitHub 上的檔案。** 存檔後約 1 分鐘 GitHub Pages 生效，三台電腦下次按書籤就是新版，**不用重裝**。

## 三、怎麼修改程式（標準流程：協作者提案 → 擁有者核准才上線）

**現場三台電腦用的是 `main` 分支。** `main` 有保護：協作者不能直接改，只能「提案」（Pull Request），**由專案擁有者看過、按 Merge 才會上線**。所以協作者怎麼改、怎麼試，都不會影響現場。

### 協作者（開發的人）
1. **先在後台測試。** 測試不需要上傳：
   - 打開後台頁面 → F12 開發人員工具 → Console，把修改後的整個檔案內容貼上執行，看效果（只影響自己這個分頁）。
   - 或用 Claude（Claude Code ＋ Claude in Chrome）幫你注入測試。
2. 上傳到**自己的分支**：GitHub 專案頁 → `Add file` → `Upload files` → 拖入檔案 → 下方選「**Create a new branch for this commit and start a pull request**」→ 分支名稱例如 `改善-檢查待接單` → `Propose changes`。
3. 在 Pull Request 寫清楚：改了什麼、為什麼、怎麼測過的（最好附截圖）。
4. 等擁有者核准。

### 擁有者（最終決定上線的人）
1. GitHub 專案頁 → `Pull requests` → 點開提案 → `Files changed` 看改了哪裡。
2. 要上線：按 `Merge pull request` → `Confirm merge`。約 1 分鐘後三台電腦生效。
3. 上線後到後台按書籤實測一次。
4. 改壞了要退回：在那個已合併的 Pull Request 頁面按 `Revert` → 再 Merge 那個退回提案，就回到上一版。

### 測試的規矩
- **接單按下去不能取消、不能退回。** 測「接單」只能用測試客戶的訂單，或事先經負責人同意的那一筆。
- 「產生出貨單」會真的在後台分配車次（只動還沒分配的訂單）。測試請用測試批次。
- 讀取、檢查類的功能可以直接在真實資料上測（只看不按）。

## 四、常態 OK 清單（Google 試算表＋Apps Script）

- 試算表欄位：狀態（待審核／核准／退回）、客戶、商品、備註內容、適用範圍（此客戶／所有客戶）、送審人、送審時間、審核時間、說明。
- 流程：小姐在「檢查待接單」按「送審成常態OK」→ 試算表新增一列「待審核」（黃色）→ **主管把狀態改成「核准」**（綠色）→ 之後檢查就算 🟢。小姐不能自己核准。
- 比對規則（保守）：客戶＋商品＋備註要**完全相同**才算（會忽略空白、全形半形、× x * 的差異）。一筆訂單只要有一個備註沒核准，整筆就是 🔴。
- 商品是「（下單備註）」的那一列，代表訂單層級的「下單備註」。

### 修改 Apps Script 的注意事項（重要）
- 在試算表 → 擴充功能 → Apps Script 修改，存檔後要**重新部署才生效**：
  `部署 → 管理部署作業 → 鉛筆（編輯）→ 版本選「新版本」→ 部署`。
  **不要用「新增部署作業」**，那會產生新網址，`accept.js` 裡的 `OK_API` 就要跟著改。
- 部署設定：執行身分＝擁有者本人、存取權＝所有人（工具不用登入 Google 就能讀清單／送審）。
- 改完把程式碼複製一份回 `apps-script/ok-list.gs` 備份。

## 四之二、更新批次價格（price.js）

取代原本的手動流程：批次「匯出訂單金額數量」→ 打開當天價格檔，複製「定價」分頁 A～L → 貼到匯出檔「盤價-定價」分頁 A1 → 存檔 → 列表頁「匯入訂單金額數量」。

- **選價格檔**：面板有下拉選單，列出最近 15 個價格檔（這個月＋上個月），**預設最新的**。價格檔由「每日報價自動備份」每天 **17:00** 產生。
- **不是今天的會警示**：選到的檔不是今天的，下拉選單下方顯示紅色警示（今天的檔還沒產生也會說明），按「更新價格」時再跳一次確認，按「取消」就不做。
- 「今天」照作業日算：**凌晨 0～6 點算前一天**（例如 11/24 凌晨 1 點按，1123 的檔就算今天，不會警示）。
- 流程：讀當天價格檔 → 每個勾選的批次：匯出（檔案只留在瀏覽器，不存到電腦）→ 填「盤價-定價」→ 照 Excel 同一個公式把「價格」欄算好 → 自動匯入 → **再匯出一次核對**後台價格。
- 後台價格只存到小數 2 位（158.3333 → 158.33），核對時照這個規則比。
- 會顯示紅色通知的情況：
  - 價格檔找不到的商品（客訂、B 級品、改過名的商品等）→ 價格欄留空，**後台原價格不變**，請手動確認。
  - 價格檔是 0 的商品 → **不會改成 0**（手動貼 Excel 會變 0），原價格不變，請手動確認。
  - 匯入後價格跟價格檔不一致。
- 「專屬價格＝O」的品項不改（跟 Excel 公式一樣）。
- 匯入會把整批的價格蓋成價格檔的價格：**要在手動改菜價之前做**，不然手動改的會被蓋回去。

### 每天提醒「價格更新了沒」（2026-11-24 加）
- 每個批次更新成功後，`price.js` 會在價格網路程式記一筆（`?action=log`，要密碼）：哪個批次、幾點、用哪天的價格檔。三台電腦共用這份紀錄（存在 Apps Script 指令碼屬性 `PRICE_UPDATE_LOG`，只留 10 天）。
- 讀紀錄 `?action=status` 不用密碼（只有批次編號和時間，沒有價格）。
- **只提醒每天第一批**（作業日最早建立的批次）：第一批有預訂單，價格要更新；第二批以後的訂單都是價格更新後才下的，不提醒（但還是可以更新）。
- 更新前會先比對：如果大部分價格本來就跟價格檔一樣、只有少數不同（看起來已經更新過，那幾項很可能是手動改的），會列出那幾項、問要不要蓋掉；結果畫面也會列出「價格有改的品項（原本 → 現在）」。
- 「今天的批次」＝作業日今天建立的批次（凌晨 0～6 點建的算前一天），不含「已停止／已中斷」。「已更新」＝有紀錄而且用的是那天的價格檔。
- 提醒出現在三個地方：
  1. **馬可小幫手選單最上面**：今天有批次還沒更新 → 17:00 前黃色提醒、17:00 後紅色警示，點一下直接打開「更新批次價格」；都更新了 → 綠色「✓ 都更新了」；今天還沒建批次就不顯示。
  2. **產生出貨單**：批次旁邊標「⚠ 還沒更新價格」／「✓ 已更新價格」。勾到今天還沒更新的批次，第一次按會出現紅色警示、按鈕變成「仍要列印（價格還沒更新）」，再按一次才列印（不用跳出視窗，避免新分頁被瀏覽器擋）。
  3. **更新批次價格**：批次旁邊標狀態；勾到已經更新過的批次會再確認（再更新會把手動改過的價格蓋掉）。
- **定時寄信**：每天 19:00 左右、凌晨 00:30 左右（還算前一天），Apps Script `checkPriceReminder` 檢查一次；今天有批次還沒更新、或一個都沒更新，就寄信給 Apps Script 擁有者。「今天有哪些批次」是小幫手讀出貨批次列表時順便回報的（`?action=status&seen=…&stop=…`，存在指令碼屬性 `PRICE_SEEN_BATCHES`）。排程用 `setupPriceReminder` 建立（執行一次會寄測試信）。
- 用舊的手動方式（Excel 匯入）更新的批次不會有紀錄，提醒會顯示「還沒更新」，確認過可直接按「仍要列印」。

### 價格密碼
- 價格網路程式要密碼才讀得到（這個專案是公開的，網址大家都看得到）。
- 密碼放在 Apps Script 專案「每日報價自動備份」→ 專案設定 → 指令碼屬性 → `PRICE_KEY`，由負責人自己設定。**程式碼和 GitHub 都不放密碼。**
- 每台電腦第一次按「更新批次價格」會要求輸入一次，只存在那台電腦的瀏覽器（不會跟著 Google 帳號同步）。面板下方「更換價格密碼」可以重輸。
- 改了密碼：每台電腦都要按「更換價格密碼」重輸一次。

### 修改價格網路程式
- 在「每日報價自動備份」專案修改，存檔後 `部署 → 管理部署作業 → 編輯 → 新版本 → 部署`。**不要新增部署**（網址會變，`price.js` 的 `PRICE_API` 要跟著改）。
- 部署設定：執行身分＝擁有者本人、存取權＝所有人。
- 改完把程式碼複製一份回 `apps-script/price-feed.gs`。

## 五、安裝到新電腦

1. 把 `installer/安裝馬可小幫手.bat` 傳到那台電腦（LINE 傳不了 .bat 就先壓成 zip）。
2. 關掉 Chrome → 對它點兩下 → 看到「馬可小幫手：已安裝」→ 按任意鍵。
3. Chrome 書籤列最左邊出現「馬可小幫手」（另有「依車號列印（備用）」：GitHub 連不上時用）。
4. 每台電腦只要裝一次。舊的「依車號列印」書籤會被自動改名成「馬可小幫手」。

改了 `installer/` 或想更新備用書籤時才需要重做安裝檔：在專案資料夾執行 `node installer/build-bat.js`。

## 六、權限與安全

| 東西 | 擁有者 | 協作方式 |
|---|---|---|
| GitHub 專案 `marco-tools` | 專案負責人（唯一管理員） | Settings → Collaborators 加協作者；協作者只能開 Pull Request，`main` 由擁有者 Merge |
| Google 試算表＋Apps Script | 專案負責人的 Google 帳號 | 試算表「共用」加對方 Gmail 為編輯者（編輯者也能改 Apps Script） |
| 馬可後台 | 各自的後台帳號 | 測試要有「車次分配」「接單」權限 |

- **`main` 分支保護**（擁有者設定一次）：Settings → Rules → Rulesets → New branch ruleset：名稱「保護正式版」、Enforcement＝Active、Bypass list 加 `Repository admin`、Target 選 `Include default branch`、勾 `Restrict deletions`、`Require a pull request before merging`（Required approvals＝1）、`Block force pushes` → Create。
- 只有擁有者能改 Settings、加減協作者、刪除專案。協作者離開時：Settings → Collaborators → Remove。
- **能 Merge 到 main 的人，就能改三台電腦上按鈕的行為** → 擁有者請開兩步驟驗證。
- 這個專案是**公開的**（GitHub Pages 免費版需要公開）：**不要放密碼、token、個人信箱、客戶資料**。
- 不要直接用後台的登入 token 呼叫 API；工具一律透過後台自己的頁面操作。

## 七、後台的眉角（改程式前必讀）

- **自有訂單列表** `/order/own`：分頁「待審核(N)」；每列第一欄是 客戶名稱／採購單位／訂單編號；列中第一個 `YYYY-MM-DD` 是期望配送日期；訂單內部 id 在 React fiber 的 `key`。
- **後台會記住篩選條件**（localStorage `defaultOrderFilterData`）。工具在隱藏 iframe 裡會先按「清除」再重新載入，否則會漏單。
- 分頁上的筆數一開始會先顯示 0，要等「全部(N)」載入、數字穩定後再讀。
- **訂單詳情** `/order/detail/{id}`：抬頭「客戶名稱/採購單位」下一行是狀態；「下單備註」沒填時顯示「無」。
- **商品備註**不是寫在商品名稱裡，而是商品那一列**下方另外一列灰色、只有一個儲存格**的列。商品名稱旁的「時價」不是備註。
- 詳情頁右上「接單」按鈕（旁邊是「取消訂單」，絕對不要碰）。接單後狀態變「已接單」。
- 車次分配：`/delivery-batch/edit/{批次id}?pageType=vehicle`，「以車次顯示」可「新增車次」，「以訂單顯示」勾選後「分配車次」選車名，後台自動編號 A01…。
- 出貨明細：`/delivery-batch/edit/{批次id}/picking-detail?orderIds=…`，每張單是 `.product-section`。

## 八、日期規則
「檢查待接單」預設日期：早上 6 點以後按 → 明天；凌晨 0～6 點按 → 今天（作業時間是中午到凌晨一兩點，做的都是隔天出貨）。畫面上可以手動改日期。
